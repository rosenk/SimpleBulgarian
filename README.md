# Simple Bulgarian: прост български за AI агенти

Simple Bulgarian е skill за AI агенти. Той кара модела да пише технически текст на ясен български език. Правилата идват от [ASD-STE100 Simplified Technical English](https://www.asd-ste100.org/). Това е контролираният английски език, с който авиацията пише ръководствата за поддръжка от 1983 година. Тук правилата са пренесени към българската граматика.

Проектът е българска адаптация на [SimpleEnglish](https://github.com/AminBlg/SimpleEnglish) (версия 2.1.2, лиценз MIT). Структурата на skill-а, hook-овете и линтерът следват оригинала. Правилата, примерите, речникът и линтерът са написани наново за български.

Skill-ът работи във всеки агент, който чете стандарта [Agent Skills](https://agentskills.io): Claude Code, Cursor, VS Code Copilot, OpenAI Codex, Gemini CLI, OpenCode и други. Той няма зависимости.

## Инсталиране

Claude Code:

```bash
claude plugin marketplace add rosenk/SimpleBulgarian
```

```bash
claude plugin install simple-bulgarian@simple-bulgarian
```

Plugin-ът добавя hook при старта на сесията, проверка на Markdown файловете и проверка на отговора. Той добавя и стил на изхода (output style) с името `simple-bulgarian:simple-bulgarian`. Изберете стила в `/config`, в раздела „Output style“, или добавете `{"outputStyle": "simple-bulgarian:simple-bulgarian"}` в `~/.claude/settings.json`.

Codex:

```bash
codex plugin marketplace add rosenk/SimpleBulgarian
```

```bash
codex plugin add simple-bulgarian@simple-bulgarian
```

Codex иска да одобрите hook-а преди първото му изпълнение. Hook-овете изискват Node.js и Python 3. Подробностите са в [`src/hooks/README.md`](src/hooks/README.md).

Ако пазите локално копие на хранилището, можете да подадете пътя до него вместо `rosenk/SimpleBulgarian`, например `claude plugin marketplace add ~/src/SimpleBulgarian`.

Само skill-а, без hook-ове: копирайте директорията `skills/simple-bulgarian` в директорията за skills на вашия агент (за Claude Code това е `~/.claude/skills/`).

Агентът не поддържа skills? Поставете блока с правилата от [`prompts/system-prompt.md`](prompts/system-prompt.md) в системния промпт, в `AGENTS.md` или в `.cursorrules`. Страницата завършва с кратка версия за тесни промптове.

После поискайте технически текст на български или кажете „преработи това на прост български“.

## Правилата

Има два регистъра в [`SKILL.md`](skills/simple-bulgarian/SKILL.md). Пълният каталог на правилата, с номерата от ASD-STE100 Issue 9, е в [`rule-catalog.md`](skills/simple-bulgarian/references/rule-catalog.md).

Отговорът, всеки отговор в чата:

| Правило | Какво премахва |
|---|---|
| Проза по подразбиране, списък или таблица само за съдържание с тази форма, без удебеляване | Стената от форматиране около отговор от един ред |
| Първото изречение отговаря | Встъплението |
| Без тирета между твърдения | Слепената половин мисъл |
| Определение на понятието с няколко думи | Жаргона, който читателят трябва да търси |
| Без встъпления и заключителни фрази | „Чудесен въпрос!“ и „Надявам се това да помогне!“ |

Документът: документация, README, ръководства, съобщения за грешки, бележки към версии:

| Правило | Какво премахва |
|---|---|
| До 20 думи в инструкция, до 25 в описание | Безкрайното изречение |
| Условие преди команда | „...ако флагът е зададен“ в края, след като читателят вече изпълни командата |
| Прости времена, деятелен залог, без деепричастия | „беше актуализиран“, „, правейки го лесно“ |
| Без „би“, „би трябвало“, „следва да“, „евентуално“ | Увъртането. Остават „може“, „ще“, „трябва“ |
| Една дума, едно значение в целия документ | Въртележката „проверете / верифицирайте / потвърдете / валидирайте“ |
| Пълна граматика, правилно членуване, „че“ остава | Телеграфния стил |
| Не повече от две „на“ подред | „стойността на времето за изчакване на пула на връзките“ |
| Без канцеларщина | „осъществяване на“, „посредством“, „с оглед на“ |
| Без удебелени начала, без заглавие над две изречения | Украсата, която крие факта |
| Факт, а не важност | „ключов“, „надежден“, „не просто X, а Y“ |

Има два режима. Обикновеният режим е по подразбиране и включва всичко по-горе. Строгият режим добавя контролиран речник с по един глагол за всяко действие от [`strict-vocabulary.md`](skills/simple-bulgarian/references/strict-vocabulary.md). Той се включва, когато поискате „строг режим“, „контролиран език“, STE или подготовка за превод. Отговорът остава в Обикновен режим във всеки режим.

## Какво е различно от английския оригинал

ASD-STE100 описва само английски език. Затова някои правила се промениха:

- Английското правило за членовете („keep articles“) стана правило за правилно членуване (пълен и кратък член).
- Забраната на „-ing“ форма след запетая стана забрана на деепричастието („правейки“) и на дългия причастен оборот („файлът, съдържащ“).
- Забраната на present perfect стана забрана на минало неопределено време („е добавил“ → „добави“).
- Модалните думи: „може“, „ще“, „трябва“ са позволени. „Би“, „би трябвало“, „следва да“, „евентуално“ и „вероятно“ са забранени.
- Веригата от съществителни стана верига от „на“.
- Добавено е правило срещу канцеларщината и срещу жаргона от английски („деплойнете“, „къмитнете“).
- Строгият режим използва собствен речник на проекта, защото за български официален контролиран речник няма.
- Правописът е по Официалния правописен речник на БАН, с кавички „…“.

## Линтер

[`evals/bg_lint.py`](evals/bg_lint.py) брои механичните нарушения. В изреченията той намира дълги изречения, забранени модални думи, минало неопределено време, страдателен залог, деепричастия и причастни обороти. В думите и знаците той намира точка и запетая, тирета, съкращения, слоп, канцеларщина, вериги от „на“ и смяна на синоними. Той не е граматичен анализатор и не вижда членуването и избора на думи.

Нарочно лошият пример не е нарушение. Оградете го с `<!-- bg-lint off -->` и `<!-- bg-lint on -->`. Линтерът пропуска текста между двата коментара, а читателят не вижда коментарите. Без `<!-- bg-lint on -->` линтерът пропуска текста до края на файла. Думата или фразата в кавички „…“ линтерът брои като една дума и не я проверява.

```bash
python3 evals/bg_lint.py --type procedural --detail docs/runbook.md
```

```bash
python3 evals/bg_lint.py --self-test
```

Hook-ът на Claude Code пуска линтера след всеки запис на Markdown файл и проверява всеки отговор в чата. Той пропуска текст, в който кирилицата е под половината от буквите. Така hook-ът не пречи на английските файлове.

Оригиналният проект има и бенчмаркове на няколко модела. Тази адаптация още няма бенчмаркове. Числата от README на SimpleEnglish не важат за нея.

## Лиценз

MIT, както оригинала. Проектът преразказва правилата за обучение и не възпроизвежда текст от стандарта или от речника му. Това е неофициален проект, който не е свързан с ASD и STEMG и не е одобрен от тях. ASD-STE100 е регистрирана търговска марка на ASD.
